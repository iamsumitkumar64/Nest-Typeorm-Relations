================================================================================
TypeORM & Relational Database Key Insights: Relations & Migrations
================================================================================

1. THE CORE INSIGHT: One-to-One vs. One-to-Many Migrations
--------------------------------------------------------------------------------
Are the migrations for One-to-One and One-to-Many/Many-to-One the same?

YES, ALMOST ENTIRELY — WITH EXACTLY ONE CRITICAL DIFFERENCE: `isUnique: true`.

At the SQL / Relational Database level:
A One-to-One relationship is fundamentally a Many-to-One relationship with
a UNIQUE constraint placed on the foreign key column.

Comparison in Migrations:
--------------------------------------------------------------------------------
• One-to-One (Book -> User):
  {
      name: 'userId',
      type: 'int',
      isNullable: true,
      isUnique: true     <-- Enforces that no two books can share the same user!
  }

• One-to-Many / Many-to-One (Books -> User):
  {
      name: 'userId',
      type: 'int',
      isNullable: true   <-- Multiple books CAN reference the same user!
  }

In both cases:
- The parent table ('users') has: `id`, `name`.
- The child table ('books') has: `id`, `title`, `userId`.
- The foreign key constraint ('FK_books_userId') points from books(userId) to users(id).


2. WHAT HAPPENS AT THE APPLICATION LAYER (TypeORM Entities)?
--------------------------------------------------------------------------------
Even though the database tables are 99% identical, TypeORM entity decorators
define how the ORM maps and queries these relationships:

• One-to-One:
  - User: 
          @OneToOne(() => Book, (book) => book.user)
          book: Book;

  - Book: 
          @Column({ nullable: true, unique: true })
          userId: number;

          @OneToOne(() => User, (user) => user.book, { onDelete: 'CASCADE' })
          @JoinColumn({ name: 'userId' })
          user: User;

• One-to-Many / Many-to-One:
  - User:
          @OneToMany(() => Book, (book) => book.user)
          books: Book[];   <-- An array instead of a single object

  - Book:
          @Column({ nullable: true })
          userId: number;

          @ManyToOne(() => User, (user) => user.books, { onDelete: 'CASCADE' })
          @JoinColumn({ name: 'userId' })
          user: User;


3. WHERE DOES Many-to-Many FIT IN?
--------------------------------------------------------------------------------
Unlike 1:1 and 1:N, a Many-to-Many relationship CANNOT be represented with a
foreign key directly on either entity's table.

Instead, it requires a third table — a Junction / Join Table ('user_books'):
- 'users' table: id, name
- 'books' table: id, title
- 'user_books' table (Junction Table):
    - user_id (PK, FK -> users.id)
    - book_id (PK, FK -> books.id)

In TypeORM:
- The owning side uses @JoinTable().
- Both sides define arrays: books: Book[] and users: User[].


4. QUICK SUMMARY CHEAT SHEET
--------------------------------------------------------------------------------
Relation Pattern       | Foreign Key Location         | Unique Constraint? | Join Table?
-----------------------|------------------------------|--------------------|------------
One-to-One             | On Owning Table (e.g. books) | YES (isUnique:true)| NO
One-to-Many/Many-to-One| On "Many" Table (e.g. books) | NO                 | NO
Many-to-Many           | On Separate Junction Table   | Composite PK       | YES
